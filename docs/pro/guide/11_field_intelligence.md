# Developer Field Intelligence

**Pro.** What practitioners actually hit in the field — the failures, workarounds,
and "is it worth it" verdicts that official docs never tell you.

## Sources

Stack Overflow, Reddit + **Reddit Answers**, Hacker News, Lobsters, and YouTube
(transcripts, chapters, comments).

## Reddit Answers research mode

Genesis searches developer-style queries and then opens the original threads:

```
"<tool> problems"        "<tool> not working"    "<tool> production issues"
"<tool> vs <alt>"        "<tool> worth it"       "<tool> migration"
"<tool> setup"           "<tool> bugs"
```

It extracts pain points, then **verifies** them against GitHub, docs, Stack
Overflow, releases, and changelogs.

## YouTube learning mode

Analyzes transcripts and chapter structure, identifies repeated recommendations
and repeated mistakes, extracts implementation techniques, compares multiple
videos, detects consensus, and verifies important claims against stronger
sources.

## The verification rule (binding)

> Reddit and YouTube are **high-value field intelligence and learning sources,
> but they are not final technical truth.**

Every important claim sourced from the field is verified against official docs,
source code, GitHub issues, release notes, and security sources before it
influences a recommendation. In an Evidence Pack, field findings are tagged as
field intelligence — never presented as authoritative truth.

> Routing note: Reddit/Instagram/X and other login-gated or blocked platforms are
> reached through dedicated connectors, never through generic scraping that fails
> on them. Field intelligence is a *market signal* tier — it informs, it never
> overrides engineering truth.
