# Repository root: what stays and why

Every file at the repository root, with a decision and the evidence behind it. A file stays at
the root when a tool, a platform or a CI check expects it there.

## Files

| File | Decision | Why |
|---|---|---|
| `README.md`, `LICENSE`, `CHANGELOG.md`, `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, `SECURITY.md`, `CITATION.cff` | KEEP | Community-health and citation files that GitHub recognises at the root |
| `AGENTS.md`, `CLAUDE.md` | KEEP | Agents load them from the root. See [AGENTS.md](../../AGENTS.md) |
| `SKILL.md` | KEEP | The skill definition; installers expect it at the root |
| `pyproject.toml` | KEEP | Packaging; its version feeds the facts chain |
| `manifest.json`, `plugin.json` | KEEP | Plugin metadata; checked by `scripts/public_surface/validate_public_claims.py` |
| `ARCHITECTURE_INVARIANTS.json` | KEEP | Input to the facts chain, read by tests and scripts |
| `ARCHITECTURE_EVIDENCE.md` | KEEP | Generated by `scripts/evidence_pack.py`; referenced by CI, code, tests and docs. Moving it would break those references for no gain |
| `.gitignore`, `.gitattributes`, `.editorconfig` | KEEP | Tool conventions |
| `.gitleaks.toml`, `.lychee.toml` | KEEP | Secret scan and link check configuration, found at the root by default |
| `sonar-project.properties` | KEEP, DEFER fix | Sonar reads it from the root. It still says `sonar.projectVersion=2.3.0`, which is stale. Left unchanged because it alters analysis labelling; update it in a change that can run the Sonar scan |

## Directories

| Directory | Decision | Why |
|---|---|---|
| `src/`, `tests/`, `scripts/`, `site/`, `docs/`, `demo/`, `docker/`, `examples/`, `references/`, `data/`, `evals/`, `assets/`, `validation/`, `.github/`, `.claude/` | KEEP | Each is referenced by code, CI or documentation |
| `genesis-architect-pro/` | KEEP | Historical source of the former Pro package. Not edited, not deleted |
| `case_studies/` | MOVED to `docs/case-studies/` | Nothing referenced the old path; it is documentation and now sits where docs are link-checked |

## How to decide for a new file

1. Does a tool or platform require the root? Keep it there.
2. Otherwise, search for references (`git grep`) and CI usage before moving anything.
3. Move with `git mv` so history follows, and update every reference in the same commit.
