Voice Agent — Builder Brief

Field notes for the agent building the Genesis voice companion, distilled from the Vercel AI Gateway voice reel (@eliron.giny, 30 Jun 2026) and checked against the code we already ship.

Source IG reel · Vercel AI Gateway voice / AI SDK 7 (beta) Current code voice/pipeline.py · voice/listener.py Stance local-first, borrow the behaviors not the cloud

00 The one-line takeaway

Read this even if you read nothing else.

The reel is not a blueprint — it's a behavior spec. The underlying tech (speech-to-speech) is a year old, and it's cloud-only, so it conflicts with our local-first design. What's worth stealing is the three conversational behaviors that make a voice bot feel alive: knowing when the user stopped, shutting up when interrupted, and acting mid-sentence. Our current pipeline does none of the three yet. That's the work.

01 Verdict at a glance

What to adopt, watch, and skip from the reel.

Adopt

Barge-in, real end-of-turn detection, and mid-turn context prefetch — implemented locally.

Watch

AI SDK 7 audio-in/out as an opt-in cloud tier only. Keep the same interface so it slots in later.

Skip

Vercel gateway as the default path. It needs a network hop + API key and would send audio off-device.

  • Wake word exists but is transcript-based: it records a 2s window, transcribes the whole thing, and substring-matches "genesis"/"ג'נסיס". Works, but see the watch-outs below.

03 The three behaviors to build

This is the heart of the brief. Ranked by value.

1 · Real end-of-turn detection (streaming VAD)

Priority 1

Replace fixed-duration recording with a live VAD that ends the turn when the user goes quiet. Today we force everyone to talk in ≤6s bursts and cut them off; the reel's bot "knows when you stopped."

How: stream mic frames through an InputStream callback into a ring buffer; run a lightweight VAD per frame (webrtcvad or Silero VAD ONNX — both local, tiny) and close the utterance after ~500–800ms of trailing silence. Then transcribe the captured span.

Touches: voice/listener.py — new streaming path alongside _record(); keep listen_once() as the PTT fallback.

2 · Barge-in (interrupt while speaking)

Priority 1

When the user starts talking, the assistant must go silent immediately. Right now TTS plays to completion — sd.play(..., blocking=True) — and nothing can stop it. This is the single biggest "feels clunky" fix.

How: make playback interruptible — swap blocking playback for a non-blocking stream you can sd.stop(), guarded by a threading.Event. Run the VAD from behavior #1 during playback; on detected speech onset, stop playback and start capturing. Full-duplex: mic stays open while speaking.

Touches: voice/pipeline.py — _play_kokoro/_play_mms/_play_espeak need a shared cancel token; add TTSPipeline.stop().

3 · Mid-turn context prefetch (our version of "function calls mid-conversation")

Priority 1

The reel's flashiest feature is the model running an action mid-sentence. We can match the feel without cloud: as soon as a partial transcript names a file/module, fire the Knowledge-Graph / fragility lookups in parallel, so results are ready the instant the user finishes. Response feels instant.

How: on partial transcript → extract entity → asyncio.create_task the context fetch; on final transcript → await the (already-running) task and hand pre-loaded context to the engine before TTS.

# voice/pipeline.py — sketch
def on_partial_transcript(self, partial: str):
    entity = self.entity_extractor.extract(partial)
    if entity:
        self._prefetch = asyncio.create_task(self.context.fetch(entity))

def on_final_transcript(self, text: str):
    ctx = await self._prefetch   # already done or nearly
    result = self.gde.run(text, context=ctx)
    self.tts.speak(result.summary)

Touches: new partial/final transcript hooks in the listener + an entity extractor. Full design already in docs/pro/INSTAGRAM_REEL_RESEARCH_REPORT.md §3.1.

04 Watch-outs in the current code

Things that will bite once you add real-time behavior.

Wake-word latency & cost

Refactor

Transcribing a full 2s window every loop just to check for "genesis" is heavy and adds ~1–2s of lag before the assistant reacts. Keep the transcript-based path as the honest default, but slot a real wake model (openWakeWord / Porcupine) behind the same is_wake() interface — the code already anticipates this. Gate the heavy STT behind cheap VAD so you only transcribe when there's actual speech.

Temp-file WAV per utterance

Perf

_transcribe_array() writes a temp .wav to disk and re-reads it for every transcription. Fine for PTT, too slow for a streaming loop. Feed audio arrays to faster-whisper in memory instead.

Don't break this invariant

Local-first is the moat. Code and file contents never leave the machine. Even if we add a cloud voice tier later, only the synthesized natural-language query and reply may cross the network — never code, never the codebase graph. Any barge-in / VAD / prefetch work must hold this line.

05 The cloud tier (later, opt-in)

Where the Vercel path actually fits.

If we ever offer a lowest-latency, most-natural mode, AI SDK 7 audio-in/audio-out (OpenAI / xAI realtime via the gateway) is the right integration — it gives barge-in and turn-detection server-side, and keeps the API key off the client. Build behind a cloud_tier=True flag routing through the same VoicePipeline interface so the local and cloud modes are swappable. Default stays local. This is Watch, not now.
