Genesis maps **50 user-facing capabilities** to a command, in 9 families. 13 further modules are internal plumbing with no command of their own.

This count is different from the number of registered engines on the home page. Engines are the units the decision engine schedules; capabilities are the things a person can ask for. Several capabilities run inside one engine, and some engines serve several capabilities.

## How to read the tables

| Column | Meaning |
|---|---|
| Maturity | `stable`: default install, covered by tests. `optional`: needs an extra or an external tool. `experimental`: no direct test coverage yet |
| Writes | What it can leave behind. `.genesis/ and reports` stays inside the project's own state folder and generated reports; `files on disk` is always opt-in or a dry run first |
| Needs | Network, LLM and optional dependencies |

A row with `Writes: nothing` does not change your files. Commands that write state, such as `recover`, `harden` and `decide`, put it under `.genesis/` and in generated reports. The machine-readable source is `data/public-capabilities.json`.
