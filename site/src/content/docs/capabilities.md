Genesis has **55 user-facing capabilities** in 9 families. 14 further modules are internal plumbing with no command of their own.

Each capability has a door, the way you reach it. 52 are `genesis` commands, 1 is a Python module entry point (`python -m ...`) and 1 is served by the Genesis MCP server. 1 has no door yet and is marked `none yet`.

Workflows are not counted here. Starting a new project, recovering an existing one and hardening a codebase are sequences of these capabilities, and the full new-project build is performed by the agent skill. The check scripts that skill runs along the way (citation, pitfall-coverage and scaffold smoke checks under `scripts/`) are steps of that workflow, not separate capabilities. Integrations such as the optional Completion Guardian are external tools and are not counted either.

This count is different from the number of registered engines on the home page. Engines are the units the decision engine schedules; capabilities are the things a person can ask for. Several capabilities run inside one engine, and some engines serve several capabilities.

## How to read the tables

| Column | Meaning |
|---|---|
| Maturity | `stable`: default install, covered by tests. `optional`: needs an extra or an external tool. `experimental`: no direct test coverage yet |
| Writes | What it can leave behind. `.genesis/ and reports` stays inside the project's own state folder and generated reports; `files on disk` creates or removes files outside `.genesis/`; the row's note says where, and anything that deletes is a dry run until you pass `--apply` |
| Needs | Network, LLM and optional dependencies |

A row with `Writes: nothing` does not change your files. Commands that write state, such as `recover`, `harden` and `decide`, put it under `.genesis/` and in generated reports. The machine-readable source is `data/public-capabilities.json`.
